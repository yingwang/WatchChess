# 重复局面与选招

本版本采用固定版本 Fairy-Stockfish 的 AXF_CHASING 判定，属于亚象联棋例的引擎实现，不声称完整实现中国象棋协会《象棋竞赛规则（2020版）》的人工裁决程序。亚象联官方棋例见 https://www.asianxiangqi.org/axf_rules.htm 。

普通循环且双方均无违规时可以判和。单方长将，以及引擎识别出的违规长捉，判违规方负。兵卒、将帅、真根与假根等情形不能只按“连续攻击一个子”判断，因此界面不自行拼写简化的长捉算法。

应用每次人类走子后、AI 走子后，均将从初始局面开始的完整着法序列交给引擎，再执行只读的 `watchresult` 命令。该命令在空闲时读取 `Position::is_game_end(result, 0)`，而非读取搜索树内的预测分数；同时处理将死与困毙。悔棋后重新提交缩短的历史，重开后从空历史开始。

原先的“三次重复一律判和”已删除。重复时不断扩大选招分差的逻辑也已删除，避免以损失棋力换取变着。MultiPV 出现杀棋分数时直接使用引擎 bestmove；只有主线路对应 bestmove，且候选深度一致、分数精确时才在原有分差范围内选择其他着法。

规则引擎异常时暂停并显示“裁决失败，请重开”，不伪造和棋结论。游戏内的裁决是自动执行的，不包含线下比赛的申诉、裁判通知与变着宽限流程。复杂棋例的覆盖能力受固定上游引擎版本限制。

## 可复现验证

`scripts/build-fairy-engine.sh` 从固定上游版本创建独立构建目录，并应用仓库内的 `scripts/fairy-adjudicate.patch`。不修改另一个 agent 正在使用的上游工作树。

`scripts/test-adjudication.py <engine>` 验证普通重复、尚未达到重复次数、悔棋后的历史、双方颜色的长将、炮长捉、兵卒例外、双方长将与困毙。加入 `--serial <已确认的手表序列号>` 可验证推到手表上的独立二进制。脚本不安装、不启动应用。报告保存在项目 `build/adjudication/`。
